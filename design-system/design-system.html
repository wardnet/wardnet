01

Principles

The five rules every screen has to pass before shipping.

01

Numbers earn the room

Stats are the loudest thing on a page. Tabular figures, large weight, no decoration. If a number isn't there, no chart fills the space.

02

Status before chrome

Every surface answers "is it healthy?" within 200ms of load. Green chip, red chip, or absence — never "checking…".

03

Mono for facts

IPs, MACs, ports, hashes, durations — all monospaced. Sans is for people; mono is for machines.

04

Surfaces, not pages

The shell never moves. Content swaps inside the canvas; the sidebar is the only navigation. No tab graveyards, no breadcrumb soup.

05

Dense without crowded

Comfortable density by default, compact for power users. Both modes use the same components — nothing collapses, everything just tightens.

06

Action lives on the right

Reading flows left → right; commits land at the end. Cancel left, primary right. Delete is always red, always last.

08

Voice

Direct, technical, never breathless. Errors are useful, not apologetic.

Do

"United States tunnel hasn't handshaken in 22 days. Bring it up?"

Specific subject, specific number, one verb-led action.

Don't

"Oops! Looks like one of your tunnels might be having trouble. Want to try reconnecting?"

Apologetic, vague, two qualifiers in one sentence.

Do

"Revoke lease for Galaxy S24 Pedro?"

Names the device. Reversible action stays one click away.

Don't

"Are you sure you want to remove this device from your network?"

Vague pronouns. "Are you sure" never adds information.

Do

"Filter is on. 4,747 of 1.25M queries blocked today."

State + number + window. The shape of every status line.

Don't

"Your DNS filtering is currently active and protecting your network."

"Currently", "your", "protecting" — all filler.

09

Forms & edit mode

Detail pages are stacks of cards. Each card flips between read and edit independently.

PATTERN

Card-level edit, not page-level

A device has Identity, Settings, DNS filtering, Network — four cards, four independent edit toggles. No global "Edit page" button. The user only enters the section they care about.

PATTERN

Read mode is the default

Open in read mode showing labeled values. The Edit button sits top-right of each card. Click it → fields become inputs, Cancel + Save dock at the bottom-right of the card.

Field rules

01 · LABELS

Always above

11px uppercase, +6% tracking, --ink-3. Never inline placeholders as labels — placeholders disappear when typing.

02 · GROUPING

2-column grid

Cards lay out fields in a 2-col grid (1-col on mobile). Long fields like WireGuard configs span both columns.

03 · IMMUTABLE

Read-only stays read-only

MAC, first-seen, manufacturer never enter edit mode. They render as plain mono text in both modes.

04 · ACTIONS

Cancel left, Save right

Bottom-right of the card. Save is the only primary button on the page while editing. ⌘+Enter saves, Esc cancels.

05 · VALIDATION

Inline, on blur

Red 1px border + 12px error text below the field. Save stays disabled until everything's valid. No toast spam.

06 · DESTRUCTIVE

Lives outside cards

"Delete tunnel", "Revoke lease" sit at the bottom of the page in a danger-toned button — never inside a settings card.

10

Charts

Network data has a shape. Match the chart to the question.

QUESTION

"How much, over time?"

→ Throughput line chart. Two series max — Download (accent), Upload (info). Dual line, soft-fill area below. Always include a window selector (1h / 6h / 24h / 48h / 12mo).

QUESTION

"Is it trending?"

→ Sparkline. No axes, no labels. Last 24h or last 60 samples. Lives inside a stat tile to give the number context.

QUESTION

"What's the breakdown?"

→ Donut or stacked bar. Donut for ≤4 categories with a headline number in the middle (e.g. blocked %). Stacked bar for ranked top-N (top blocked domains, top talkers).

Chart rules

01 · COLOR

Two series max per chart

Download = --accent, Upload = --info. Categorical charts cycle accent → info → warn → ink-3. Never invent a new chart palette.

02 · GRID

Horizontal hairlines only

4 horizontal grid lines using --line at stroke-dasharray:2 4. No vertical gridlines, no tick marks.

03 · AXES

Numbers, not headers

Y-axis: 4 mono labels with a unit (KB/s, MB, %). X-axis: timestamps in 24h. No axis titles — the card title carries it.

04 · WINDOW

Always selectable

Pill group: 1h · 6h · 24h · 48h · 12mo. Selected pill uses --bg-card with --shadow-card. Window total ("↓ 3.1 GB · ↑ 186.7 MB") sits under the chart title.

05 · BRUSH

Time-series ≥ 24h gets a brush

Mini overview track below the main chart, accent-tinted. Drag to zoom. 12mo views always show it.

06 · EMPTY

"No data yet" — never zeros

If the device just connected, render the grid + a centered --ink-4 "Collecting…" label. A flat-zero line lies about the data.

07 · LEGEND

Bottom-center, mono dots

Tiny circle + label, mono 11px. No legend if there's only one series — the card title says what it is.

08 · TOOLTIP

Card style, hover only

Use --bg-card + --shadow-pop. Mono timestamp + bold value per series. No animation on enter.

12

Tabs & sub-views

Tabs split a single page into 2–5 grouped views. Underline style only — quiet, scannable, never the loudest thing on the page.

01 · WHEN

Group, don't navigate

Use tabs only when the views share a subject — Devices: Managed / Unmanaged. Same noun, different filter. If a tab needs its own URL outside the parent, it's a sidebar item, not a tab.

02 · STYLE

Underline, not pill

Tabs sit on a baseline hairline. Active tab gets a 2px --ink bar; inactive tabs are --ink-3. Reserve the pill .tabs control for time-window selection inside charts — never as page nav.

03 · COUNT

5 max

Past 5 tabs the page is two pages. Hard cap. Counts in tab labels are mono and parenthesized: Managed (28).

04 · URL

Persist in ?tab=

Active tab is a query param so reload + share work. Default tab has no param. Switching tabs replaces history (no back-button graveyard).

05 · COUNTERS

Right of label, mono, muted

Counts use --ink-4 with mono. Active tab's counter promotes to --ink-2. No badges, no dots — counts already say "look here".

06 · CHROME

One row, no scroll

Tabs sit just under the page H1, above the first card. They never wrap, never horizontal-scroll. If they would, fix the count, not the layout.

13

Solo charts

The chart that owns its card. Line is the default — throughput, latency, query rate. Always windowed, always brush-able past 24h.

Anatomy

A · TITLE BLOCK

Top-left, two lines

Line 1: card title in 14px semibold (Throughput / Latency / Queries). Line 2: window total in mono 11px --ink-3 — "Window total: ↓ 3.1 GB · ↑ 186.7 MB". Always present, even at zero.

B · WINDOW SELECTOR

Top-right pill group

Fixed steps: 1h · 6h · 24h · 48h · 30d · 12mo. Default is 24h. Selected pill uses --bg-card + --shadow-card. Component: .tabs (re-used).

C · PLOT AREA

200–240px tall · viewBox-scaled

Soft-fill area below the line at color-mix(--accent 12-14%, transparent). Stroke is 1.6–1.8px --accent. 4 horizontal gridlines, dashed stroke-dasharray:2 4. No vertical gridlines.

D · BRUSH

Mini overview track, 32px tall

Below the main plot for any window ≥ 24h. Drag the handles to slice — main plot zooms, window pill stays. Handles are 4px wide, --accent; track fill is --accent-soft.

E · LEGEND

Bottom-center, mono 11px

Skip if single series. For two: Download (●) · Upload (●). Dot color matches the line. No interactive toggling — both series are always on.

F · TOOLTIP

Card style, follows cursor

--bg-card + --shadow-pop, 1px line. Mono timestamp on top, then ↓ 1.2 MB/s + ↑ 240 KB/s. Vertical guideline pinned to the cursor's nearest sample, 1px --ink-4.

14

Editing data

Two patterns, picked by stakes. Card-edit for things the user composes; auto-save for things they toggle.

PATTERN A · CARD EDIT

For composed values

Use when the user is filling out a related set of fields together — the device's Identity, Settings, Network. Read mode is the default; Edit button top-right of the card. Editing one card never blocks editing another. Cancel + Save dock at the bottom-right of the card. Save is the only primary on the page while editing.

PATTERN B · AUTO-SAVE

For independent switches

Use when each control is its own decision — DNS filtering on/off, Auto-update channel, Default profile. The control commits on change; no Save button. Toast bottom-right confirms ("DNS filtering enabled"). On failure, a toast with Retry reverts the value.

Field anatomy

1 · LABEL

Always above

Sentence case, 13px, weight 500, --ink. Not uppercase — uppercase labels are reserved for read-mode data points (MAC, Last seen). Editable form fields use sentence-case labels so they read like a question the user is answering.

2 · DESCRIPTION

Optional, between label and control

12px, --ink-3, single line where possible. Use it to explain consequence, not to repeat the label. "Applied to devices that have no explicit profile assignment." ✓   "Choose a default profile" ✗.

3 · CONTROL

Below description, full-column width

Inputs/selects fill the column. Toggles + radios are intrinsic-width and right-align inside their row. 8px gap label→description, 6px gap description→control.

Layout grid

2-COLUMN DEFAULT

Two fields per row, 24px column gap, 18px row gap

Cards lay fields out as grid-template-columns: 1fr 1fr. Long values (WireGuard config, descriptions) span both columns with grid-column: 1 / -1.

1-COLUMN STACK

For action-style controls

Settings page rows ("Safe Reboot", "Auto-update channel") are label + description on the left, control on the right — single-column rows separated by hairlines. Pattern B always uses this; Pattern A uses 2-column.

FULL-WIDTH

Code & long text

WireGuard configs, multi-line names, IP-octet inputs — span both columns. Mono textareas use --bg-sunken not --bg-elev so the field reads as code, not prose.

RESPONSIVE

Below 720px → 1 column

2-column collapses to 1 at @media (max-width: 720px). The shell handles the breakpoint; field components don't need their own media queries.

Save semantics

CARD · SAVE

Toast bottom-right

"Device settings saved." Auto-dismiss 4s. ⌘+Enter commits, Esc cancels. Save is disabled while validation is pending.

CARD · DIRTY NAV

Confirm before leave

If the user navigates away from a page with an open edit card holding unsaved changes: "Discard changes to Settings?" · Cancel · Discard. Closing the tab uses beforeunload.

AUTO · COMMIT

Optimistic + revert

UI updates immediately. Toast confirms ("Channel set to Beta"). On failure, revert and toast "Couldn't save. Retry" with a Retry action — danger-toned, 6s dismiss.

AUTO · DEBOUNCE

Text inputs wait 600ms

Toggles/selects commit on change. Free-text fields debounce 600ms after the last keystroke; show a faint "Saving…" in the description slot, replaced by "Saved" for 2s.

VALIDATION

Inline, on blur

Border turns --danger, 12px error text replaces the description. Save (Pattern A) stays disabled until clean. Pattern B refuses commit and toasts the error.

DESTRUCTIVE

Outside cards, page-bottom

"Delete tunnel", "Revoke lease", "Restore from backup" sit at the page bottom in a danger-toned button. Confirm dialog names the subject: "Delete Portugal Dedicated IP?". Never inline inside a settings card.

16

Tailwind bridge

The system ships a tailwind.config.js so you can write utilities (bg-card text-ink rounded-lg) or hand-written component classes (.card .btn--primary) — both compile against the same CSS variables in styles.css. Theme + density toggles flip everything in lockstep; Tailwind never bakes hex.

SOURCE

CSS vars stay canonical

Every token in §02–04 lives in :root. Tailwind references them by var(--…). Never paste hex into a utility — it breaks dark mode and density.

DARK

data-theme, not class

Config uses darkMode: ['selector','[data-theme="dark"]'] so the existing token blocks work unchanged. dark: variants flip with the theme attribute.

MIX

Compose freely

The two systems are layered, not exclusive. Use .card for the container, then Tailwind utilities for one-off layout inside it. Don't reinvent .btn--primary as utilities — call the class.
