# Wardnet 2026.09.00

A follow-up to [`2026.08.01`](v2026.08.01.md) about cross-zone casting, and about a DHCP interop bug the previous release believed it had already fixed.

Casting from a phone to a TV in another zone now has a configuration that works, a rejected exception explains itself instead of failing silently, and a device that happens to be switched off can no longer take your zone isolation down with it. The DNS query log gets substantially smaller on disk and faster to page through.

> [!IMPORTANT]
> **`GET /api/dns/log` no longer returns `total`.** It is replaced by `has_more` (exact, not an estimate — the daemon fetches one row beyond the limit and reports whether it materialised) and `next_cursor`. Counting matching rows meant an unbounded `COUNT(*)` over the largest table on the box, measured at ~300 ms per page load against ~1 ms for the rows it accompanied. The admin UI ships with this release and needs nothing from you. If you call the endpoint yourself, drive "next page" from `has_more` rather than comparing an offset against `total`, and render a row range from the offset and `entries.length`. `@wardnet/js` 0.7.0 and `wardnet.network/go` 0.3.0 carry the change.

## Bug fixes

### Mesh access points really do stop restarting now

[`2026.08.01`](v2026.08.01.md) claimed this fixed. It was not, and the reason is worth stating plainly: that fix corrected which *address* a reply is sent to, having diagnosed the problem as a client that sets the BROADCAST flag. A packet capture on the same live network shows the opposite — the access point sends `flags=0x0000` and never sets the flag at all. Wardnet was setting it, on every `DHCPOFFER` and `DHCPACK`, regardless of what the client asked for. A client that reads the field and finds a delivery mode it never requested discards the reply, so it never registers the acknowledgement, retransmits at the RENEWING floor of 60 seconds for the life of the lease, and eventually starts over from `DHCPDISCOVER` — which is broadcast, and therefore works. Each of those restarts drops every Wi-Fi client on that access point. Replies now carry back the client's own BROADCAST bit and nothing else; the other fifteen flag bits are reserved and stay zero rather than being reflected back onto the segment. A `DHCPNAK` is still always broadcast. [#1331](https://github.com/wardnet/wardnet/pull/1331)

### A device that is switched off no longer disables all zone isolation

Discovery clears a device's stored address the moment it departs, so a cross-zone exception naming a device that is merely powered off resolved to an address of `/32` with nothing in front of it. The firewall rejects that, and the ruleset is applied as a unit — so one absent device dropped **every** allow and **every** cross-zone deny on the box, leaving a segmented network with no isolation at all. On the network where this was found, adding an exception while the far device was off took the ruleset from 34 allows and 20 cross-zone denies to zero, and said so in a single warning that the "reconciled" line logged immediately afterwards made easy to miss. An exception whose endpoint has no current address is now skipped on its own, and returns by itself when the device is next seen. [#1331](https://github.com/wardnet/wardnet/pull/1331)

### Casting from a phone that is itself the media source

The `casting` service preset opens the ports a receiver needs to be *told* what to play — mDNS, SSDP, Chromecast, AirPlay. That is enough when the TV fetches the media itself, and not enough when the phone is the source: screen mirroring and local files negotiate an ephemeral port, which is a new flow the established-connection exemption does not cover, so the zone's cross-deny dropped it. The cast connected, ran for a few seconds, died, and retried. The `mirroring` preset exists for exactly this and the daemon has always supported it, but the admin UI never offered it, so there was no working configuration to choose. It is now in the service list, labelled as what it is: all ports, between two named devices only. [#1331](https://github.com/wardnet/wardnet/pull/1331)

### A refused cross-zone exception now tells you why

The daemon answers an invalid exception with the reason in the response body — a full-range service whose endpoints are not both devices, an endpoint that no longer exists, an inverted port range. None of it reached the screen: the form had no channel for a failure, so a rejected save looked exactly like one that silently did nothing, and the only way to find out was to open the browser's developer tools and read the raw response. The reason is now shown on the form, and cleared when the form is reopened or cancelled. [#1331](https://github.com/wardnet/wardnet/pull/1331)

### Recursive resolution no longer fails on domains that dislike QNAME minimization

In recursive mode, strict QNAME minimization made some authoritative servers return nothing for names that resolve correctly under a relaxed query. Minimization is now relaxed where those servers require it, so the names resolve. [#1328](https://github.com/wardnet/wardnet/pull/1328)

## Improvements

### The DNS query log takes about a quarter of the disk it used to

The log's seven repeated text columns move onto lookup tables and the timestamp becomes an epoch integer. On a measured box the table went from 591 MB to **146 MB** — 109 MB from the normalisation itself, plus the integer indexes it cannot run correctly without. This is a space change, not a speed one, and nothing above the data layer knows the lookup tables exist: the API contract is unchanged. [#1325](https://github.com/wardnet/wardnet/pull/1325)

### Paging the query log is no longer slower the further back you look

The admin log's client filter resolves its substring against the client-address table before touching the log, so a single matching client becomes an indexed seek rather than a scan — measured at 0.3 ms against 19.7 ms at 1.37M rows for a client whose rows have aged. Pagination moves from an offset to a cursor, and the page-total count is gone (see the callout above). [#1329](https://github.com/wardnet/wardnet/pull/1329), [#1324](https://github.com/wardnet/wardnet/pull/1324)

## Upgrading

### Auto-update (recommended)

Open **Settings → Updates** in the admin UI and apply the update.

Note the callout above before upgrading:

- If you call `GET /api/dns/log` yourself, `total` is gone — page on `has_more` and `next_cursor` instead. The admin UI needs no action.

### Manual installer

```sh
curl -sSL https://wardnet.network/install.sh | sudo bash
```

## Targets in this release

| Target | Architecture |
|--------|-------------|
| Raspberry Pi (3 and newer) and other `aarch64` Linux SBCs | `aarch64-unknown-linux-gnu` |
| Mini-PCs, `x86_64` servers, and other non-Pi Linux hosts | `x86_64-unknown-linux-gnu` |

Wardnet needs a 64-bit OS — there is no 32-bit (`armv7`) build. On a Raspberry Pi, use the 64-bit Raspberry Pi OS.
