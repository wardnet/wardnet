# Wardnet 2026.07.00-beta.6

Patch beta following [`2026.07.00-beta.5`](v2026.07.00-beta.5.md). The headline is infrastructure rather than a feature you'll click: a new **edge release channel** that lets a build go from a branch onto real hardware in minutes instead of an hour — the groundwork for a faster fix-test loop on the betas that follow. Alongside it are a handful of correctness fixes: the DNS query log now labels every outcome instead of showing several as "unknown", the fallback DNS-over-HTTPS resolver talks to Google on the right endpoint again, the admin and user mobile apps install side by side instead of colliding, and the installer's `--channel` flag actually selects the channel you name. Beta builds receive updates via the **beta channel** only — switch to it in **Settings → Updates** to opt in.

> [!IMPORTANT]
> A fresh, ground-up beta install is supported with `curl -fsSL https://wardnet.network/install.sh | sudo CHANNEL=beta bash`. The installer's `CHANNEL` only selects **which tarball is fetched** — the daemon's auto-update channel is stored separately and still defaults to `stable`. After a fresh beta install you **must** set the channel to `beta` in **Settings → Updates**, or the box will not receive further beta updates. It will not downgrade; it will simply sit on this build.

## Bug fixes

### The DNS query log labels every outcome instead of showing "unknown"

Several resolution outcomes had no display label, so the query log showed them as a bare "unknown" result: a domain that genuinely has no record of the asked type (NODATA), a name that doesn't exist in an authoritative zone (NXDOMAIN), a query dropped by rate limiting, one blocked as a DNS-rebinding attempt, and a recursive lookup that failed upstream. All five now carry their own result badge, so the log tells you what actually happened to a query rather than lumping five distinct outcomes under one opaque label. The same change also quiets a class of per-query resolver noise in the admin UI's live log and error feed (it stays in the log file) so the events an admin can act on aren't drowned out. Closes [#906](https://github.com/wardnet/wardnet/pull/906).

### The fallback DNS-over-HTTPS resolver reaches Google again

When the daemon needs to resolve a name over HTTPS as a fallback (used in the remote-access path), it queries Cloudflare and Google for redundancy. Both speak the same JSON schema but at different paths: Cloudflare answers JSON on `/dns-query`, while Google serves JSON **only** on `/resolve` and rejects a JSON request to `/dns-query` with an HTTP 400. The daemon was pointing at Google's `/dns-query`, so the Google fallback always failed and only Cloudflare ever worked. It now uses Google's `/resolve` endpoint, restoring the intended redundancy. Closes [#903](https://github.com/wardnet/wardnet/pull/903).

### The admin and user mobile apps install side by side

The installable mobile PWAs — the user app at `/` and the admin app at `/admin-app/` — shared no distinct install identity, so a browser treated them as the same app: installing one could replace the other rather than adding a second icon. Each now declares a distinct manifest `id` (`/` and `/admin-app/`), so they install as two separate apps and can live on the home screen together. Closes [#904](https://github.com/wardnet/wardnet/pull/904).

### The installer's `--channel` flag now selects the channel you name

`install.sh --channel beta` (and `--channel edge`) silently installed from **stable**: the manifest URL was computed from the environment before the `--channel` argument was parsed, so the flag was ignored while the script still reported the channel you asked for. The flag now resolves the manifest after parsing and validates the channel name, so `--channel` and the `CHANNEL=` environment form behave the same. Fixed as part of [#907](https://github.com/wardnet/wardnet/pull/907).

## Improvements

### An edge release channel for on-demand test builds

A third release channel, **edge**, sits above beta in risk. Edge builds are published straight from a branch by an on-demand workflow — no review, no release notes, no test gates — so a candidate fix can be signed and installed on a real Pi in minutes instead of paying the full release ceremony each iteration. They are signed with the same production key, so the channel is authentic; what's deliberately absent is any promise the code is good.

Edge is not a place a normal box should ever be. It cannot be selected from the web UI alone: following it requires `allow_edge_channel = true` in the box's `[update]` config — i.e. root on the box, not merely an admin session. A box left on edge whose flag is later removed falls back to beta on the next restart. See the [configuration docs](https://wardnet.network/docs/configuration) for the full picture. Added in [#907](https://github.com/wardnet/wardnet/pull/907).

## Upgrading

### Auto-update (beta channel)

Set the channel to **beta** in **Settings → Updates**, then apply the update as usual. The daemon binary swap is mediated by the root-owned post-upgrade runner.

### Fresh install on the beta channel

```sh
curl -fsSL https://wardnet.network/install.sh | sudo CHANNEL=beta bash
```

Then open the setup wizard at `http://<pi-ip>:7411/admin/` and set the release channel to **beta** in **Settings → Updates** once setup completes (see the note above).

### Manual installer

Re-run the installer to pick up the new daemon:

```sh
curl -sSL https://wardnet.network/install.sh | bash
```
