# Wardnet 2026.07.00-beta.2

Patch beta following [`2026.07.00-beta.1`](v2026.07.00-beta.1.md). It unblocks **remote access**: DDNS registration failed on beta.1 because the built-in region catalog pointed at a region that was never deployed. With DDNS working, the premium mobile surfaces (the user PWA and the admin mobile app) become reachable too. Beta builds receive updates via the **beta channel** only — switch to it in **Settings → Updates** to opt in.

> [!WARNING]
> **Known issue — Network Zones can lock you out of your gateway.** If a device is recorded holding the Pi's own LAN address, moving devices into an isolation zone makes the daemon enforce network policy against *itself*, and the box becomes unreachable — admin UI, SSH and ping, from every device, over every path. Recovering requires physical access. Until this is fixed, **do not create zones with the "isolate members" stance** on a gateway you cannot physically reach. Tracked as [#886](https://github.com/wardnet/wardnet/issues/886), fixed in the next beta.

> [!IMPORTANT]
> A fresh, ground-up beta install is supported with `curl -fsSL https://wardnet.network/install.sh | sudo CHANNEL=beta bash`. The installer's `CHANNEL` only selects **which tarball is fetched** — the daemon's auto-update channel is stored separately and still defaults to `stable`. After a fresh beta install you **must** set the channel to `beta` in **Settings → Updates**, or the box will not receive further beta updates. It will not downgrade; it will simply sit on this build.

## Bug fixes

### Remote access (DDNS) registration works again

Registering a hostname during setup failed with a **502 Bad Gateway**. The daemon dials a *regional* cloud gateway, and its built-in region catalog still carried the placeholder `use1` from the original design note — a region that was never deployed and whose hostname has no DNS record at all, so the call never reached anything. The catalog now points at the deployed `euc` (eu-central) region.

This is what blocked remote access on beta.1, and with it the premium mobile surfaces that are gated on it. Closes [#885](https://github.com/wardnet/wardnet/pull/885).

### The installer points you at the setup wizard, not the user app

A fresh install printed `Web UI: http://<ip>:7411`, which serves the **user PWA**. The admin site — and with it the first-run setup wizard — lives at `/admin/`, so new installers landed on the wrong app with no hint where to go. The installer now prints the wizard's address. Closes [#885](https://github.com/wardnet/wardnet/pull/885).

## Upgrading

### Auto-update (beta channel)

Set the channel to **beta** in **Settings → Updates**, then apply the update as usual. The daemon binary swap is mediated by the root-owned post-upgrade runner.

### Fresh install on the beta channel

```sh
curl -fsSL https://wardnet.network/install.sh | sudo CHANNEL=beta bash
```

Then open the setup wizard at `http://<pi-ip>:7411/admin/` and set the release channel to **beta** in **Settings → Updates** once setup completes (see the note above).

### Manual installer

Re-run the installer to pick up the new daemon:

```sh
curl -sSL https://wardnet.network/install.sh | bash
```
