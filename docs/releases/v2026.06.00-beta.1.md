# Wardnet 2026.06.00-beta.1

First beta of [`2026.06.00`](https://github.com/wardnet/wardnet/milestone/TODO), following [`2026.05.03`](v2026.05.03.md). This build introduces the new admin mobile PWA, the wardnet bridge service, a generic stats pipeline, and a range of smaller daemon improvements. Beta builds receive updates via the **beta channel** only — switch to it in **Settings → Updates** to opt in.

> [!IMPORTANT]
> The `@wardnet/js` SDK has breaking changes in this release: `DnsService.getStats()` and `TunnelService.getMetrics()` are removed (replaced by the new `StatsService`), and several `DnsQueryResult` values have been renamed (`cached` → `cache_hit`, `local` → `rewritten`). Update any code that calls these APIs before upgrading.

## Improvements

### New admin mobile PWA

A dedicated progressive web app for the admin role ships for the first time in this release. Install it from any mobile browser pointed at your gateway's `/admin` path — the browser's "Add to Home Screen" gesture installs it as a native-feeling app with offline support. The initial build covers:

- **Login and session guard** — password login with optional remember-me (30-day session), biometric unlock, and an automatic session-refresh on every open.
- **Dashboard** — summary cards for device count, tunnel health, DNS activity, and disk usage, with a persistent banner for any unclean-shutdown alert.
- **Devices list** — table of all DHCP leases with MAC, hostname, IP, and current routing target; tap a device to open its routing and DNS-filter sheet.
- **Tunnels** — status page showing each tunnel's up/down state, resolved server name, and latency; a Rebuild action tears down and re-applies the WireGuard config when a tunnel is stuck.
- **System screen** — daemon health stats (CPU, memory, disk), active tunnel count, uptime, and safe-reboot / safe-shutdown buttons.

Closes [#488](https://github.com/wardnet/wardnet/pull/488), [#492](https://github.com/wardnet/wardnet/pull/492), [#494](https://github.com/wardnet/wardnet/pull/494), [#511](https://github.com/wardnet/wardnet/pull/511), [#513](https://github.com/wardnet/wardnet/pull/513), [#514](https://github.com/wardnet/wardnet/pull/514), [#515](https://github.com/wardnet/wardnet/pull/515).

### Wardnet bridge service

A new `wardnet-bridge` backend — built on a Rust async stack with a MySQL/Neon database — provides the relay layer that lets the admin mobile app reach your gateway when you're away from home. It uses an SNI demultiplexer to route client connections to the right gateway over a persistent reverse-tunnel, with no port forwarding required. Closes [#435](https://github.com/wardnet/wardnet/pull/435), [#443](https://github.com/wardnet/wardnet/pull/443), [#444](https://github.com/wardnet/wardnet/pull/444).

### Generic stats subsystem

The previously DNS-specific stats pipeline has been replaced by a generic metrics subsystem:

- **Pre-aggregating buffer** (`StatsBuffer`) collapses per-query events into intraday and daily roll-ups, reducing write pressure on the SQLite database.
- **`/api/stats`** — flexible time-series query endpoint (single or multi-metric, configurable bucket size).
- **`/api/stats/top`** — top-N aggregation by any label key (e.g. top queried domains, top blocked clients).
- **`StatsService`** in `@wardnet/js** replaces `DnsService.getStats()` and the old tunnel metrics endpoint.

Closes [#409](https://github.com/wardnet/wardnet/pull/409), [#425](https://github.com/wardnet/wardnet/pull/425), [#427](https://github.com/wardnet/wardnet/pull/427).

### Per-tunnel latency probing

Each WireGuard tunnel now maintains a continuous latency series via the stats pipeline. Tunnel throughput metrics have been migrated from the old dedicated `/api/tunnels/:id/metrics` endpoint to the generic `/api/stats` endpoint. Closes [#430](https://github.com/wardnet/wardnet/pull/430).

### NordVPN best-server re-resolution at tunnel bring-up

"Best server" NordVPN tunnels now re-query the NordVPN recommendation API each time the tunnel is brought up, picking the lowest-load server at that moment rather than using a stale endpoint from first configuration. The previously resolved server name is preserved as `resolved_server_name` on the tunnel object and surfaced in the Tunnels UI. Closes [#447](https://github.com/wardnet/wardnet/pull/447).

### DNS filter profile descriptions

Filter profiles now carry an optional free-text `description` field (up to 200 characters). Built-in profiles ship with a seeded description; custom profiles default to `null` and can be set or cleared via `PUT /api/dns/filter/profiles/:id`. Closes [#433](https://github.com/wardnet/wardnet/pull/433).

### Daily incremental vacuum runner

A new `DbMaintenanceRunner` background task fires daily and runs `PRAGMA incremental_vacuum` to reclaim freed SQLite pages without blocking query traffic. Closes [#434](https://github.com/wardnet/wardnet/pull/434).

### Routing target included in device list response

`GET /api/devices` now returns each device's `current_rule` field — the active routing target, or `null` if the device follows the gateway default. Previously this required a separate per-device fetch. Closes [#485](https://github.com/wardnet/wardnet/pull/485).

## Bug fixes

### Log-stream WebSocket gated behind admin auth

`GET /api/system/logs/stream` (the live daemon log WebSocket) was reachable without authentication. It now requires an active admin session. Closes [#432](https://github.com/wardnet/wardnet/pull/432).

## Upgrading

### Auto-update (beta channel)

Switch to the beta channel in **Settings → Updates**, then apply the update as usual. The daemon binary swap is mediated by the root-owned post-upgrade runner.

### Manual installer

Re-run the installer to pick up the new daemon:

```sh
curl -sSL https://wardnet.network/install.sh | bash
```

## Targets in this release

- `aarch64-unknown-linux-gnu` — Raspberry Pi (3 and newer) and other aarch64 Linux SBCs
- `x86_64-unknown-linux-gnu` — mini-PCs, x86_64 servers, and other non-Pi Linux hosts
