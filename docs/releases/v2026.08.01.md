# Wardnet 2026.08.01

A follow-up to [`2026.08.00`](v2026.08.00.md) built around who is on your network and how they ask for things.

**Household identity** gives the box its own user directory, so a home is no longer a single shared admin password. **Access requests** turn Private DNS into something a household member can ask for and an admin can approve, instead of an admin-only switch. **Device identification** keeps improving — Wardnet now listens for mDNS advertisements a device already broadcasts, and an admin can run an explicit port probe against a device that stays unidentified. Devices you have actually configured are now marked **managed** and kept; ones you never touched are forgotten after 30 days away.

Underneath, the cross-zone routing that a tunnel-bound device depends on has been repaired in three separate places, and a DHCP interop bug that had been quietly restarting mesh access points around the clock is fixed.

> [!IMPORTANT]
> **Your blocklists re-import on first boot after upgrading, and filtering is inactive until they finish.** This release stores `dns_filter_blocked_domains` as a `WITHOUT ROWID` table, which reclaims roughly a third of its size — about 186 MB on a box holding 2.4M domains. SQLite cannot convert a table in place, and copying those rows across costs ~49s of blocked startup on a Pi with no DNS and no DHCP while systemd's start timeout runs. So the table is recreated empty and every blocklist is marked never-imported; the DNS filter runner re-imports them in the background shortly after boot. Nothing is lost — every row is reconstructible from its source URL — but there is a window after upgrade where ad and tracker blocking is not yet in effect.

> [!IMPORTANT]
> **Unmanaged devices absent for 30 days are now deleted.** A device becomes *managed* the moment you configure it — name it, move it to a zone, bind it to a tunnel, grant it Private DNS. Managed devices are kept indefinitely. A device you never configured and that has not been seen for 30 days is pruned, so the device list stops accumulating one-off guests forever. If you want to keep a device you have never configured, give it a name.

## Improvements

### Household identity — real users instead of one shared password

The box now keeps its own user directory, with typed principals separating an admin session from a device-derived identity. This is the groundwork for a household where people have their own accounts rather than sharing the admin login. The directory is deliberately **box-local**: wardnet-cloud may pre-fill a hint, but it never vouches for a login into your home network, which is why account recovery is local-only. Closes [#1147](https://github.com/wardnet/wardnet/issues/1147) via [#1192](https://github.com/wardnet/wardnet/pull/1192). Design: [ADR-0031](../adr/0031-household-identity.md).

### Access requests — ask for Private DNS, approve it from the admin UI

Private DNS used to be something only an admin could switch on for a device. A household member can now request it from their device, and an admin approves or declines from a single inbox. Approval is what grants the device and marks it managed — asking never does. Closes [#919](https://github.com/wardnet/wardnet/issues/919) via [#1254](https://github.com/wardnet/wardnet/pull/1254). Design: [ADR-0033](../adr/0033-household-access-requests.md).

### Devices are identified from what they already advertise

Wardnet now observes the mDNS service advertisements devices broadcast on their own and uses them as an identification signal, so a printer or a TV names itself without being asked anything ([#1183](https://github.com/wardnet/wardnet/pull/1183)). For a device that stays unidentified, an admin can trigger an explicit TCP port probe from the device page ([#1186](https://github.com/wardnet/wardnet/pull/1186)). The invariant holds: nothing probes a device without a direct admin action.

### Managed devices, "Stop managing", and 30-day retention

Configuring a device latches it as managed; a **Stop managing** action releases it and removes the admin artefacts that went with it. Unmanaged devices absent for 30 days are pruned by a background runner. See the callout above. Closes [#1181](https://github.com/wardnet/wardnet/issues/1181) via [#1185](https://github.com/wardnet/wardnet/pull/1185). Design: [ADR-0032](../adr/0032-managed-devices-and-retention.md).

### Blocklist refreshes that keep failing now raise an alert

A blocklist whose refresh keeps failing used to fail quietly, leaving you with stale filtering and no signal. Repeated failures now surface as an admin alert. Closes [#1193](https://github.com/wardnet/wardnet/pull/1193).

### Private DNS follows a roaming device's tunnel binding

A device bound to a tunnel now has its roaming DoT queries honour that binding, so encrypted DNS while away from home exits where the rest of that device's traffic does ([#1144](https://github.com/wardnet/wardnet/pull/1144)).

### `wctl` grows logs, dns, dhcp and system subcommands

The CLI can now read logs, inspect DNS and DHCP state, and query system information ([#1189](https://github.com/wardnet/wardnet/pull/1189)).

## Bug fixes

### Mesh access points no longer restart themselves around the clock

> [!NOTE]
> **This entry is wrong and the problem was not fixed.** It was written against the theory that the client sets the BROADCAST flag and the server ignores it; a later capture on the same network shows the access point sends `flags=0x0000` and never sets it. The change below is correct as far as it goes — a reply's destination should honour the flag — but it did not stop the restart cycle, and neither did the follow-up in [`2026.09.00`](v2026.09.00.md). The cause is still unknown.


A DHCP client that sets the BROADCAST flag is stating it cannot take delivery of a unicast reply. Wardnet chose the reply destination from the request's source address alone and never consulted the flag, so such a client — renewing correctly, from the address it holds — never registered the acknowledgement. It retransmitted every 60 seconds until its lease was nearly spent, then released and started over from scratch, which *is* broadcast and therefore worked. On a live network a powerline access point was doing this continuously and a mesh node was recycling its lease ~17 times a day; each cycle restarts the access point and drops the clients on it. Replies now honour the flag, a `DHCPNAK` is always broadcast (it says the address you are holding is wrong, so sending it there is self-defeating), and a relayed request goes back to its relay. Part of [#1274](https://github.com/wardnet/wardnet/pull/1274).

### Cross-zone traffic from a tunnel-bound device reaches the other zone

Three separate faults left a tunnel-bound device with its cross-zone LAN traffic captured by its tunnel — so casting to a TV in another zone, or reaching anything across zones, silently went up the WireGuard link instead. Carve-out rules were recorded as installed even when the kernel had rejected them, which happened routinely for a device whose DHCP lease had not landed yet, and the failure then latched permanently. The per-device routing rules were also left for the kernel to prioritise, which placed each one *ahead* of the very carve-outs meant to override it. Both are fixed, and the rules now occupy an explicit priority band so the ordering holds by construction. [#1274](https://github.com/wardnet/wardnet/pull/1274), with related routing fixes in [#1231](https://github.com/wardnet/wardnet/pull/1231) (member-isolation host routes now carry a preferred source) and [#1196](https://github.com/wardnet/wardnet/pull/1196) (kernel-reserved routing tables are no longer treated as Wardnet's).

### DHCP no longer stalls for every device when the database is busy

The DHCP server handled one packet to completion before reading the next, so a slow database write stalled every client at once — and the clients responded by retransmitting into a server already behind. Packets from different devices are now handled concurrently, while each device's own packets stay strictly ordered, and a burst of retransmits from one client collapses into a single answer. Part of [#1274](https://github.com/wardnet/wardnet/pull/1274).

### Anomaly alerts stop firing twice and recovering falsely

Anomalies could report a recovery that had not happened, alert twice for the same condition, and a configuration key could block boot outright. Closes [#1230](https://github.com/wardnet/wardnet/pull/1230).

### Daily database maintenance is observable and survives a restart

The daily maintenance pass now reports what it did and resumes correctly if the daemon restarts mid-run. The blocked-domains table is also collapsed onto its primary key — see the callout above. [#1190](https://github.com/wardnet/wardnet/pull/1190).

### A local DNS change evicts the whole affected subtree

Changing a local DNS record left cached answers for names beneath it in place, so the change appeared not to take effect for subdomains until the cache expired. The whole subtree is now evicted. [#1191](https://github.com/wardnet/wardnet/pull/1191).

### PWA fixes

The Private DNS deep link no longer scrolls away while the page is still settling ([#1188](https://github.com/wardnet/wardnet/pull/1188)), and the install banner stays above page content instead of being overlapped ([#1187](https://github.com/wardnet/wardnet/pull/1187)).

### Go toolchain security update

`wctl` and the Go SDK are now built on Go 1.26.6, clearing eight standard-library advisories ([#1233](https://github.com/wardnet/wardnet/pull/1233)).

## SDKs

Both SDKs are released alongside this version, from their own tags:

- **`wardnet.network/go` 0.2.0** — new `anomalies`, `dhcp`, `dns`, `logs` and `system` surfaces.
- **`@wardnet/js` 0.6.0** — adds `AccessRequestService` and `AnomalyService`. **Breaking:** `RuleRequestService` and its types are removed; the rule-request inbox was replaced by the single access-request inbox. Migrate `RuleRequestService` → `AccessRequestService`.

## Upgrading

### Auto-update (recommended)

Open **Settings → Updates** in the admin UI and apply the update.

Note the callouts above before upgrading:

- Blocklists are re-imported in the background on first boot. Ad and tracker blocking is inactive until that completes — no action needed, but expect a short gap.
- Devices you have never configured and that have been absent for 30 days will be pruned. Name any device you want to keep.
- If you consume `@wardnet/js` directly, `RuleRequestService` is gone in 0.6.0.

### Manual installer

```sh
curl -sSL https://wardnet.network/install.sh | sudo bash
```
