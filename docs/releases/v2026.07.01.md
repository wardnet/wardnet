# Wardnet 2026.07.01

A small point release on top of [`2026.07.00`](v2026.07.00.md): two bug fixes — one that gets per-device tunnel routing working on bare-metal installs that never had IP forwarding turned on, and one that stops the DNS dashboard from showing fractional query counts.

> [!IMPORTANT]
> The IP-forwarding fix ships in the **installer**, and auto-update only swaps the daemon binary — it does not re-run `install.sh`. If per-device tunnel routing was silently not taking effect on a bare-metal box, apply the fix by re-running the installer (`curl -sSL https://wardnet.network/install.sh | sudo bash`) or by enabling forwarding yourself: `echo 'net.ipv4.ip_forward = 1' | sudo tee /etc/sysctl.d/99-wardnet.conf && sudo sysctl --system`. Fresh installs and Docker (`--sysctl net.ipv4.ip_forward=1`) already had this covered.

## Bug fixes

### Per-device tunnel routing on bare-metal installs with IP forwarding disabled

Per-device VPN routing forwards LAN traffic into the WireGuard tunnels, which requires `net.ipv4.ip_forward=1`. Nothing on a bare-metal install ever enabled it: the installer didn't touch `sysctl`, and the daemon runs as an unprivileged user that cannot write `/proc/sys/net/ipv4/ip_forward` itself. On a box where forwarding wasn't already on for some other reason, traffic assigned to a tunnel simply wasn't forwarded. The installer now writes `/etc/sysctl.d/99-wardnet.conf` enabling forwarding and applies it at install time. Closes [#949](https://github.com/wardnet/wardnet/pull/949).

### DNS stat totals no longer show fractional query counts

The **Queries over time** chart's points are pre-aggregated bucket values that carry fractional components, and summing them for the window totals produced fractional numbers — visible in the "Window total" subtitle and in the Queries / Blocked stat cards when the chart is zoomed. A query count is a whole number, so this read as a bug. The totals are now rounded at the aggregation site, so every consumer shows whole queries. Closes [#940](https://github.com/wardnet/wardnet/pull/940).

## Upgrading

### Auto-update (recommended)

Open **Settings → Updates** in the admin UI and apply the update — the daemon binary swap is mediated by the root-owned post-upgrade runner. No operator action is required for the daemon itself.

Note the callout above: the IP-forwarding fix lives in the installer, so a binary-only auto-update will not apply it. If you were affected, re-run the installer or set the sysctl by hand as shown above.

### Manual installer

Re-run the installer to pick up the new daemon (and the IP-forwarding fix in one step):

```sh
curl -sSL https://wardnet.network/install.sh | sudo bash
```

## Targets in this release

| Target | Architecture |
|--------|-------------|
| Raspberry Pi (3 and newer) and other `aarch64` Linux SBCs | `aarch64-unknown-linux-gnu` |
| Mini-PCs, `x86_64` servers, and other non-Pi Linux hosts | `x86_64-unknown-linux-gnu` |

Wardnet needs a 64-bit OS — there is no 32-bit (`armv7`) build. On a Raspberry Pi, use the 64-bit Raspberry Pi OS.
