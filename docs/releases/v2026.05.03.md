# Wardnet 2026.05.03

A feature-heavy release on top of [`2026.05.02`](v2026.05.02.md). Setup discovery now works without knowing the gateway's IP, the admin UI and marketing site have been reworked around a new Wardnet design system, tunnels gain an exit-IP test, DNS filtering covers tunneled devices and reacts to filter changes, multiple default DNS profiles can stack, and unclean shutdowns surface in the dashboard.

## Improvements

### Reworked admin UI and marketing site on the new Wardnet design system

The admin app and the marketing site have both been rebuilt on top of a new shared design system that aligns them with the refreshed Wardnet brand. Same screens and flows you already know — new typography, colour, components, and motion across the board. Closes [#374](https://github.com/wardnet/wardnet/pull/374).

### `wardnet.local` mDNS advertisement for setup discovery

A new `MdnsAdvertiser` runner in `wardnetd` registers an `_http._tcp.local.` service record on the configured LAN interface, so a fresh gateway is reachable at `http://wardnet.local:7411` from anywhere on the LAN without anyone needing to know the IP. The TXT record carries `version=<WARDNET_VERSION>` and an A record for `wardnet.local.` (or a configured override) is published alongside. Closes [#349](https://github.com/wardnet/wardnet/pull/349).

### Gratuitous-ARP failover on graceful shutdown and startup

`wardnetd` now broadcasts gratuitous-ARP replies on graceful shutdown (a farewell announcement from the upstream router's MAC) and on startup (a claim announcement from the Pi's LAN MAC) so managed clients reclaim or release the gateway IP within ~1 second instead of waiting out the 1–5 minute ARP cache TTL. Closes [#213](https://github.com/wardnet/wardnet/issues/213).

### Multiple default DNS filter profiles

The gateway-wide "default profile" fallback widens from a single profile to a list, mirroring the per-device side that already accepted N profiles. Multiple profiles stack — a domain blocked in any of them is blocked. An empty list means unassigned devices skip filtering entirely. The Settings page replaces the previous `<Select>` with a multi-toggle list reused from the per-device DNS filter card. Existing single defaults are carried forward automatically on upgrade. Closes [#343](https://github.com/wardnet/wardnet/pull/343).

### Tunnel exit-IP / country test

Each tunnel card gains a **Test** button that brings the tunnel up if needed, sends one HTTP probe through the tunnel interface, and reports back `{exit_ip, country_code, latency_ms}`. Surfaced via a new `POST /api/tunnels/{id}/test` endpoint and a matching `TunnelService.test(id)` method in `@wardnet/js`. The probe URL is configurable via `tunnel.test_probe_url` (default Cloudflare `cdn-cgi/trace`). Closes [#238](https://github.com/wardnet/wardnet/issues/238).

### Unclean-shutdown detection with dashboard banner

The daemon now tracks whether the previous run ended gracefully or was interrupted (crash, `kill -9`, power loss) and surfaces unclean shutdowns as a persistent dashboard banner with a timestamp until an admin dismisses it. Implements the FR-071 / FR-075 operator-visibility requirement. Closes [#216](https://github.com/wardnet/wardnet/issues/216).

### Extended first-run setup wizard

The single-step admin-creation wizard is replaced with the full 7-step onboarding flow specified in FR-070 — FR-072, so a non-technical user can finish setup without ever opening a terminal. Closes [#222](https://github.com/wardnet/wardnet/issues/222).

### DNS cache invalidation on filter source updates

Cached DNS answers (TTL ≤ `dns_cache_ttl_max_secs`, default 1 day) used to survive filter changes — newly-blocked domains kept returning cached `Pass` answers until their TTL expired, so a blocklist edit appeared to do nothing for hours. Filter-source updates now invalidate the relevant cache entries immediately. Closes [#341](https://github.com/wardnet/wardnet/issues/341).

## Bug fixes

### Tunneled devices honour the ad-blocking filter

Devices routed through a tunnel previously bypassed ad-blocking entirely: an nftables prerouting DNAT rule silently sent their DNS to the tunnel's configured DNS server, skipping wardnet's resolver. All DNS now flows through wardnet's server regardless of routing target; per-query upstream is chosen from a lock-free `device_ip → UpstreamId` snapshot the routing service publishes, and tunneled-device upstreams are forwarded via `SO_BINDTODEVICE`-bound sockets so they still egress on the tunnel interface instead of leaking to the ISP. Closes [#342](https://github.com/wardnet/wardnet/issues/342).

### `netlink_packet_route` WARN spam silenced

`netlink_packet_route::link::buffer_tool` logs a WARN every time the running kernel returns more bytes for an attribute than the crate version knows about (e.g. `IFLA_INET6_STATS`: expecting 288, got 304). On current kernels that fires constantly and drowns out everything else. The default log filter now suppresses that specific module at `error` level. The directive is added before the user-supplied `[logging.filters]` map, so an operator who wants the warnings back can re-raise it via config. Closes [#337](https://github.com/wardnet/wardnet/pull/337).

## Upgrading

### Auto-update (recommended)

Open **Settings → Updates** in the admin UI and apply the update — the daemon binary swap is mediated by the root-owned post-upgrade runner installed in `2026.05.02`, so no operator action is required.

### Manual installer

Re-run the installer to pick up the new daemon:

```sh
curl -sSL https://wardnet.network/install.sh | bash
```

## Targets in this release

- `aarch64-unknown-linux-gnu` — Raspberry Pi (3 and newer) and other aarch64 Linux SBCs
- `x86_64-unknown-linux-gnu` — mini-PCs, x86_64 servers, and other non-Pi Linux hosts
