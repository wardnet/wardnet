# Wardnet 2026.07.00-beta.1

First beta of `2026.07.00`, following [`2026.06.00-beta.2`](v2026.06.00-beta.2.md). This is the largest release so far: Network Zones bring real device isolation to the LAN, the DNS stack grows local zones, DNSSEC, DoT/DoH and full recursive resolution, the gateway now owns its own HTTPS certificate and dynamic DNS name, Web Push lands in both mobile apps, a three-layer watchdog keeps the box alive unattended, and inbound "Personal VPN" WireGuard access arrives in preview. Beta builds receive updates via the **beta channel** only — switch to it in **Settings → Updates** to opt in.

> [!IMPORTANT]
> A fresh, ground-up beta install is now supported with `curl -fsSL https://wardnet.network/install.sh | sudo CHANNEL=beta bash`. Be aware that the installer's `CHANNEL` variable only selects **which tarball is fetched**. The daemon's auto-update channel is stored separately in its own configuration and still defaults to `stable`. After a fresh beta install you **must** switch the channel in **Settings → Updates** to `beta`, otherwise the box will not receive further beta updates. It will not downgrade — the updater never moves backwards — it will simply sit on this build until the stable line catches up.

## Improvements

### Network Zones — device isolation, quarantine, and casting

Devices can now be grouped into **zones** (e.g. Trusted, Kids, Guest, IoT) with real enforcement behind them, rather than a label:

- **Per-zone subnets and member isolation** — each zone gets its own subnet; members of an isolated zone cannot reach each other or hosts in other zones.
- **Per-zone egress policy** — nftables forward-chain rules drop the tunnel/WAN egress a zone is not allowed to use, live-reloaded on every zone or device change with a conntrack flush so the rule takes effect immediately rather than at the next connection.
- **Admin-UI gating** — devices in a zone that isn't admin-reachable are refused at the gateway's admin ports, so a guest laptop can't even reach the login page.
- **Cross-zone exceptions and casting** — explicit exceptions let a phone in one zone drive a TV in another, and mDNS/casting discovery keeps working across the boundary instead of being collateral damage of the isolation rules.
- **New-device quarantine** (off by default) — a device seen for the first time can be held in a quarantine zone until an admin approves it, with pending approvals surfaced in the UI.
- **UI everywhere** — zone management, membership, and approvals in the admin site, the admin mobile PWA, and a read-only zone summary for the user PWA.

Closes [#743](https://github.com/wardnet/wardnet/pull/743), [#749](https://github.com/wardnet/wardnet/pull/749), [#750](https://github.com/wardnet/wardnet/pull/750), [#754](https://github.com/wardnet/wardnet/pull/754), [#761](https://github.com/wardnet/wardnet/pull/761), [#765](https://github.com/wardnet/wardnet/pull/765).

### Local DNS zones, daemon-owned HTTPS, and dynamic DNS

The gateway is now a proper authoritative resolver for your own network, and it can hold its own public name and certificate:

- **Local DNS records** — define A/AAAA/CNAME/TXT records for your LAN under your own domain and have the gateway answer them authoritatively, ahead of the cache, filter, and upstreams. Changes take effect immediately (the authoritative view is rebuilt on change, no restart).
- **Daemon-owned TLS** — `wardnetd` obtains and renews its own certificate over ACME and terminates HTTPS itself. No reverse proxy to install, configure, or keep alive.
- **Dynamic DNS** — a pluggable DDNS provider layer keeps your gateway's name pointed at your current WAN IP, either through the Wardnet service (with region selection based on measured latency) or your own Cloudflare account (bring-your-own domain).

Closes [#600](https://github.com/wardnet/wardnet/pull/600).

### DNSSEC, DNS-over-TLS / DNS-over-HTTPS, and recursive resolution

The resolver gains the privacy and integrity features you'd expect from a dedicated DNS box:

- **DNSSEC validation** of upstream answers.
- **DoT and DoH upstreams** so queries leaving your network are encrypted instead of plaintext UDP/53.
- **DNS rebinding protection** and per-client **rate limiting**.
- **Recursive mode** — resolve from the root servers yourself, with no upstream forwarder in the path at all.

Closes [#635](https://github.com/wardnet/wardnet/pull/635), [#637](https://github.com/wardnet/wardnet/pull/637).

### Forwarder routing modes, per-upstream latency, and Quad9 by default

When you do forward, you now choose how: **Failover** (ordered list), **Fastest** (race the upstreams), or **Single**. A background prober continuously measures each upstream's latency and surfaces it in the admin UI so the choice is informed rather than a guess. Quad9 joins the default upstream set via a guarded migration. Configuration is validated before it is persisted, so a rejected change never half-writes the resolver config. Closes [#768](https://github.com/wardnet/wardnet/pull/768).

### Per-device DNS activity and self-service rule requests

Per-device DNS event capture (opt-in per device) streams the queries a device is actually making, delivered live to the UI over a Server-Sent Events channel. The user PWA gets a personal DNS stats view, a capture toggle, and the ability to **request** that a blocked domain be unblocked — the request lands in the admin's notification feed rather than requiring a text message to whoever runs the network. Closes [#605](https://github.com/wardnet/wardnet/pull/605), [#607](https://github.com/wardnet/wardnet/pull/607), [#613](https://github.com/wardnet/wardnet/pull/613).

### Web Push notifications in both mobile apps

The daemon now manages VAPID keys and delivers Web Push notifications directly to installed PWAs — no third-party push relay in the middle. Admins get a notification feed in the admin mobile app with alerts for events such as rule requests; users can subscribe from the user PWA with a device-keyed toggle. Dead subscriptions are pruned automatically. Closes [#747](https://github.com/wardnet/wardnet/pull/747), [#791](https://github.com/wardnet/wardnet/pull/791), [#792](https://github.com/wardnet/wardnet/pull/792).

### Three-layer watchdog and health monitoring

An unattended gateway now recovers from its own failures. A `HealthMonitor` continuously runs health checks (with per-check timeouts and consecutive-failure debouncing) and publishes a snapshot over an unauthenticated `GET /health` endpoint. That snapshot gates a **soft watchdog**: if the daemon is unhealthy, systemd restarts the service. Below that sits an **ungated hard watchdog** on `/dev/watchdog` — if the daemon stops petting the hardware at all, the kernel reboots the host. Closes [#683](https://github.com/wardnet/wardnet/pull/683).

### Per-tunnel speed test with direct-vs-tunnel comparison

Each tunnel gains a speed test that measures throughput **through** the tunnel and compares it against a direct measurement on the same link, so you can see the real cost of routing a device through that VPN provider rather than guessing. Closes [#696](https://github.com/wardnet/wardnet/pull/696).

### Inbound WireGuard — "Personal VPN" (preview)

The foundation for inbound WireGuard has landed: the gateway can run as a WireGuard **server**, so you can dial home from your phone or laptop and use your own network's DNS, filtering, and routing while you're away. This is a Premium feature and is gated accordingly, with peers torn down when entitlement lapses. Closes [#819](https://github.com/wardnet/wardnet/pull/819), [#860](https://github.com/wardnet/wardnet/pull/860).

### Redesigned first-run setup wizard

The setup wizard has been rebuilt around a fixed-shape guided rail: a stable rail/body/footer shell, new **DNS** and **Review** steps, and the ability to rewind to any earlier step (down to the network floor) without losing what you've already entered. Closes [#790](https://github.com/wardnet/wardnet/pull/790).

### Remote access over the Wardnet cloud service mesh

The previous single-bridge remote-access model is replaced by a per-service cloud mesh: the daemon holds an Ed25519 identity, proves possession of it on every call, and onboards with a short **enrollment code** instead of manual key handling. Premium app surfaces (the user PWA and the admin mobile app) are gated on entitlement; the desktop admin site and the whole `/api/*` surface — including the plain-HTTP LAN fallback on `:7411` — stay reachable on every tier, so you can always administer the box and (re)subscribe. Closes [#726](https://github.com/wardnet/wardnet/pull/726), [#788](https://github.com/wardnet/wardnet/pull/788), [#793](https://github.com/wardnet/wardnet/pull/793), [#795](https://github.com/wardnet/wardnet/pull/795).

### New branding and a shared design system across every surface

A refreshed Wardnet brand — new icon, wordmark, and colour system — is applied across the admin site, both PWAs, the marketing site, and the API reference. Under it sits a real design system (`@wardnet/ui`, published with Storybook, CSS Modules, and a two-tier typography scale) that every surface now consumes, so the three apps finally look like one product. The marketing site has been reworked for launch with a cloud-optional story, a Premium page, and a multi-version API reference. Closes [#633](https://github.com/wardnet/wardnet/pull/633), [#649](https://github.com/wardnet/wardnet/pull/649), [#684](https://github.com/wardnet/wardnet/pull/684), [#770](https://github.com/wardnet/wardnet/pull/770), [#794](https://github.com/wardnet/wardnet/pull/794).

### DHCP: safe pool changes, hostname suggestions, and richer lease rows

- **Pool-range changes no longer strand devices.** Editing the DHCP pool now revokes out-of-range leases, NAKs renewals for addresses that are no longer valid so clients cleanly re-DISCOVER, and hot-reloads the running DHCP server without a daemon restart. A preview endpoint powers a pre-save warning listing exactly which devices will be affected. Closes [#753](https://github.com/wardnet/wardnet/pull/753).
- **Reservation hostnames are auto-suggested** from the managed device whose MAC you just typed, instead of making you retype it. Closes [#763](https://github.com/wardnet/wardnet/pull/763).
- **Reservation descriptions show in the leases table** as a subline under the hostname, and are searchable; a reserved MAC no longer appears twice in the combined view. Closes [#756](https://github.com/wardnet/wardnet/pull/756).

### Firewall rules applied over pure netlink

`wardnetd` now programs nftables directly over netlink instead of shelling out to the `nft` CLI. Rule application is faster, atomic, and no longer depends on a matching `nft` binary being installed on the host. Closes [#682](https://github.com/wardnet/wardnet/pull/682).

### Daemon relicensed to GPL-3.0-or-later

The `wardnetd` daemon is now licensed under **GPL-3.0-or-later**. The `@wardnet/js` SDK remains **MIT**, so it can continue to be embedded freely in downstream and closed-source clients. If you redistribute a modified daemon, the GPL's source-availability obligations now apply to you. Closes [#825](https://github.com/wardnet/wardnet/pull/825).

### `@wardnet/js` published to npm

The TypeScript SDK is now published to npmjs.org and can be installed like any other package, instead of only being consumable in-repo. Closes [#806](https://github.com/wardnet/wardnet/pull/806).

### Expired admin sessions are cleaned up automatically

A background runner now prunes expired sessions from the database instead of letting them accumulate for the life of the install. Closes [#752](https://github.com/wardnet/wardnet/pull/752).

## Bug fixes

### Admin login works again over plain HTTP on `:7411`

The session cookie was always issued with the `Secure` attribute, which browsers silently drop over `http://`. Since the pre-provisioning admin surface is plain HTTP on `:7411`, logging in there stored no cookie and every following request returned `401`. `Secure` is now set only on connections that actually arrive over TLS. As part of the same fix, both PWAs now activate a waiting service worker immediately, so an upgraded app shell reaches already-installed clients instead of waiting for every tab to close. Closes [#766](https://github.com/wardnet/wardnet/pull/766).

### Restoring a backup no longer silently reverts to pre-restore data

The database runs in WAL mode, and the restore path swapped the main database file while a stale write-ahead log was still present — so changes made before the restore could resurrect afterwards, and the restored data could be partially lost. The restore now handles the WAL correctly, and a full export → modify → restore round-trip is covered by an end-to-end test. Closes [#695](https://github.com/wardnet/wardnet/pull/695).

### Malformed config is rejected at startup instead of ignored

Unknown or misspelled keys in `wardnet.toml` were silently ignored, so a typo'd setting appeared to be applied but wasn't. Every config struct now rejects unknown fields and fails loudly at startup. The database path default is also now the absolute `/var/lib/wardnet/wardnet.db`, so a zero-config daemon no longer tries to create an unwritable database in the filesystem root, and the resolved path is logged in the startup banner. Closes [#755](https://github.com/wardnet/wardnet/pull/755).

### Auto-update on the beta channel orders pre-release versions correctly

Pre-release versions (`-beta.N`) were compared incorrectly, which could make the updater see a newer beta as older than the release it was built from. Version ordering is fixed, a failed update's automatic rollback now restarts the daemon rather than leaving it down, and a DNS-filter query bug surfaced by the same work is fixed. Closes [#520](https://github.com/wardnet/wardnet/pull/520).

### Security advisories patched

Vulnerable transitive dependencies flagged by RUSTSEC advisories (`memmap2`, `quinn-proto`, `cmov`, RUSTSEC-2026-0173, RUSTSEC-2026-0190) have been patched. Closes [#692](https://github.com/wardnet/wardnet/pull/692), [#759](https://github.com/wardnet/wardnet/pull/759), [#789](https://github.com/wardnet/wardnet/pull/789).

## Upgrading

### Auto-update (beta channel)

Switch to the beta channel in **Settings → Updates**, then apply the update as usual. The daemon binary swap is mediated by the root-owned post-upgrade runner.

### Fresh install on the beta channel

A ground-up beta install is supported:

```sh
curl -fsSL https://wardnet.network/install.sh | sudo CHANNEL=beta bash
```

> [!IMPORTANT]
> `CHANNEL=beta` only tells the **installer** which tarball to download. It does not set the daemon's auto-update channel, which lives in the daemon's own configuration and still defaults to `stable`. After the install completes and you finish the setup wizard, open **Settings → Updates** and set the release channel to **beta**. If you skip this step the box will not track future beta releases.

### Manual installer

Re-run the installer to pick up the new daemon:

```sh
curl -sSL https://wardnet.network/install.sh | bash
```
