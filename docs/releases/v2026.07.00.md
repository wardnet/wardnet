# Wardnet 2026.07.00

The first stable release since [`2026.05.03`](v2026.05.03.md), and by some distance the largest so far — the whole `2026.07.00` beta cycle promoted in one step.

Wardnet grew three new surfaces in this cycle. **Network Zones** turn a flat LAN into segmented groups with their own subnets and egress rules. **Personal VPN** lets your phone dial back into your own network from anywhere, rather than only routing outbound. And two **installable mobile apps** — one for admins, one for everyone else in the house — put the parts of Wardnet each audience actually needs on their home screen.

Underneath that, the DNS stack went from "forwards to an upstream" to a resolver in its own right: it can now recurse from the root servers itself, validate DNSSEC, speak DoT and DoH, rate-limit floods, block rebinding attacks, and attribute every query to the device that made it.

## Improvements

### Network Zones

A flat LAN treats a guest laptop and a work machine identically. Zones split the network into groups, each with its own subnet, and enforce the split at the gateway:

- **Per-zone subnets and member isolation** — devices in a zone get addresses from that zone's range, and zones are isolated from one another.
- **Per-zone egress rules** — a zone can be forbidden from reaching a tunnel or the WAN entirely, enforced in the nftables forward chain.
- **Admin-UI gating** — a zone can be barred from reaching the Pi's own admin surfaces, while DNS and DHCP still pass.
- **Cross-zone exceptions and casting** — targeted holes for the cases that need them, so a phone can still cast to a TV in another zone.
- **New-device quarantine** (off by default) — hold unknown devices in a restricted zone until an admin approves them.

One honest limit: two devices sharing a subnet can still talk to each other directly, because that traffic never reaches the Pi. Isolation is enforced at the gateway, not on the wire. Closes [#735](https://github.com/wardnet/wardnet/issues/735), [#754](https://github.com/wardnet/wardnet/pull/754), [#750](https://github.com/wardnet/wardnet/pull/750), [#761](https://github.com/wardnet/wardnet/pull/761), [#765](https://github.com/wardnet/wardnet/pull/765).

### Personal VPN — dial back into your own network

An inbound WireGuard server, so a device off the LAN can reach your network as though it were at home: grant a device access, scan the QR code once, and it connects back in. Credentials are per-device, can be paused without revoking, and are shown exactly once at grant time. A Premium feature. Closes [#266](https://github.com/wardnet/wardnet/issues/266), [#812](https://github.com/wardnet/wardnet/issues/812), [#860](https://github.com/wardnet/wardnet/pull/860).

### Two installable mobile apps

- **User app** (at `/app/`) — for everyone in the house. See and change your own device's route, watch your own DNS stats, toggle query capture, and request a filter rule change.
- **Admin app** (at `/admin-app/`) — a phone-shaped admin surface: dashboard, devices, tunnels, DNS, and system health, with a biometric gate on the session.

Both install to the home screen as separate apps, work offline for the shell, and can receive push notifications. A Premium feature. Closes [#435](https://github.com/wardnet/wardnet/issues/435)–[#441](https://github.com/wardnet/wardnet/issues/441), [#516](https://github.com/wardnet/wardnet/pull/516), [#613](https://github.com/wardnet/wardnet/pull/613).

### Remote access without port-forwarding

Reach your box from outside without opening a port on your router: the daemon dials out to the Wardnet cloud mesh and is reachable through it, with a dynamic-DNS name and daemon-owned TLS. Includes a region catalog that probes for the closest region, and Cloudflare as an alternative DNS provider. Closes [#521](https://github.com/wardnet/wardnet/issues/521), [#527](https://github.com/wardnet/wardnet/issues/527), [#726](https://github.com/wardnet/wardnet/pull/726).

### A real DNS resolver

- **Recursive resolution** — resolve from the root servers directly instead of trusting an upstream. Closes [#219](https://github.com/wardnet/wardnet/issues/219).
- **DNSSEC validation, DNS rebinding protection, and per-client rate limiting**, plus **DoT / DoH** for upstream queries. Closes [#218](https://github.com/wardnet/wardnet/issues/218).
- **Forwarder routing modes** — Failover, Fastest, or Single, with a background latency probe per upstream surfaced in the UI. Quad9 is added as a default upstream via a guarded migration. Closes [#636](https://github.com/wardnet/wardnet/issues/636).
- **Per-device query attribution** — the query log and stats name the device that asked, resolved at query time rather than guessed later. Closes [#924](https://github.com/wardnet/wardnet/pull/924).
- **Local DNS names** — reach the box as `wardnet` from the LAN, plus authoritative local records. Closes [#217](https://github.com/wardnet/wardnet/issues/217), [#930](https://github.com/wardnet/wardnet/pull/930).

### Tunnel speed tests and latency

Measure what a tunnel actually costs you: a per-tunnel speed test compares direct against tunneled throughput and reports the percentage of your line you keep, plus a continuous latency probe per tunnel. Closes [#239](https://github.com/wardnet/wardnet/issues/239).

### Self-healing

A three-layer recovery stack: a health monitor tracks each subsystem, a health-gated software watchdog restarts the service when one stays unhealthy, and an ungated hardware watchdog reboots the host if the daemon stops responding entirely. Closes [#214](https://github.com/wardnet/wardnet/issues/214).

### Statistics

A pre-aggregating metrics pipeline behind the dashboard — DNS and tunnel time-series and top-N queries that stay cheap to read on a Pi. Closes [#409](https://github.com/wardnet/wardnet/issues/409).

### Smaller things

- **Setup wizard redesign** — guided rails, DNS and Review steps, and the ability to go back. Closes [#790](https://github.com/wardnet/wardnet/pull/790).
- **New branding** across every surface. Closes [#633](https://github.com/wardnet/wardnet/pull/633).
- **nftables via netlink** instead of shelling out to the `nft` CLI. Closes [#307](https://github.com/wardnet/wardnet/issues/307).
- **DHCP**: pool-range changes no longer strand devices ([#227](https://github.com/wardnet/wardnet/issues/227)); reservation hostnames auto-suggest from the matching device ([#85](https://github.com/wardnet/wardnet/issues/85)).
- **Edge release channel** for on-demand builds, gated behind a root-only config flag. Closes [#907](https://github.com/wardnet/wardnet/pull/907).
- **Alphabetical device and tunnel lists** everywhere, so a device sits in the same place on every screen. Closes [#935](https://github.com/wardnet/wardnet/pull/935).

## Bug fixes

These are fixes to behaviour that existed in `2026.05.03`. Fixes made *during* the beta cycle to features that never shipped stable are folded into their feature descriptions above rather than listed here — from `2026.05.03` there was nothing to see.

### DHCP advertises the Wardnet DNS server while it is enabled

With the built-in DNS server enabled, DHCP still handed clients the configured upstream resolvers instead of Wardnet itself, so devices that took their DNS from DHCP quietly resolved unfiltered — the ad-blocking was on, and simply not being used by anything. DHCP now advertises the Wardnet resolver whenever it is enabled. Note that DHCP is pull-based: a device keeps the resolver from its current lease until that lease renews, so reconnect a device to apply the change immediately. Closes [#899](https://github.com/wardnet/wardnet/pull/899).

### Negative DNS answers are relayed instead of becoming SERVFAIL

A domain that genuinely has no record of the type asked for (NODATA), or a name that does not exist (NXDOMAIN), were both turned into SERVFAIL — which clients read as "the resolver is broken" rather than "there is no such record", and retry against it. Both are now relayed as the negative answers they are, with RFC 2308 negative caching so repeat lookups don't re-ask upstream. Closes [#896](https://github.com/wardnet/wardnet/pull/896).

### The Pi stops blackholing its own IP when a device claims it

If a device on the LAN claimed the Pi's own address, the daemon would install rules against it and effectively blackhole itself. It now recognises its own addresses and leaves them alone. Closes [#886](https://github.com/wardnet/wardnet/issues/886).

### ACME certificate issuance waits for DNS to propagate

TLS certificate issuance could fail — and then stall for 12 hours before retrying — because validation ran before the DNS record it depends on had propagated. Issuance now waits for propagation, backs off in a rate-limit-aware way, and the retry stall is gone. Closes [#892](https://github.com/wardnet/wardnet/pull/892).

## Upgrading

### Auto-update (recommended)

Open **Settings → Updates** in the admin UI and apply the update — the daemon binary swap is mediated by the root-owned post-upgrade runner. No operator action is required.

If your box is on the **beta** channel and you want to return to the stable line, set the channel back to **stable** in **Settings → Updates**. This build is `2026.07.00-beta.6` plus everything that landed after it — per-device DNS attribution, the bare `wardnet` name, the user app's move to `/app/`, alphabetical device and tunnel lists, and assorted fixes — so it is a step forward from beta.6, not a downgrade.

### Manual installer

Re-run the installer to pick up the new daemon:

```sh
curl -sSL https://wardnet.network/install.sh | bash
```

## Targets in this release

| Target | Architecture |
|--------|-------------|
| Raspberry Pi (3 and newer) and other `aarch64` Linux SBCs | `aarch64-unknown-linux-gnu` |
| Mini-PCs, `x86_64` servers, and other non-Pi Linux hosts | `x86_64-unknown-linux-gnu` |

Wardnet needs a 64-bit OS — there is no 32-bit (`armv7`) build. On a Raspberry Pi, use the 64-bit Raspberry Pi OS.
